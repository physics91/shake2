# 쉐이크2 복원: 원본과 같은 글자(GDI 비트맵 글꼴)

## Goal

캔버스에 그리는 모든 글자를 원본 shake.exe(0311)가 Windows GDI로 그린 것과 픽셀 단위로 같게 만든다. 지금은 브라우저 글꼴을 50% 덮임에서 잘라 흉내 내므로 글자 모양과 세로 1px이 원본과 다르다(FIDELITY §6 글꼴, R).

## Evidence (부모가 확인)

- **글꼴을 만드는 코드**: `0x418370`이 `CreateFontA(높이, 0, 0, 0, 굵기, 0, 0, 0, 0x81, 0, 0, 0, 0, 이름)`를 부른다.
  - 굴림체 12 → `[0x4939c0]`(기본), 11 → `c4`, 13 → `c8`, 14 → `cc`
  - 굴림체 13 굵게 → `d0`
  - Fixedsys 13(문자 집합 0) → `d4`
  - Courier New 15(문자 집합 0x81) → `d8`
- **글꼴을 고르는 코드**:
  - `0x418dd0(n)`: n = 11/12/13/14/15에 해당 글꼴, 그 밖은 12.
  - 호출 285곳의 인자는 13(175), 12(68), 15(9), 14(7)이다. 11은 없고, 0x13·0x1e·0x12a는 모두 12가 된다.
  - 굵은 13(`0x418e20`)과 Fixedsys(`0x418e40`)는 장면 6(쓰이지 않는 옛 대기실, `0x435820`)에서만 쓰인다.
- **글꼴을 그리는 방식**: Shake1 스크린샷 `screen_b01.gif`의 이름 두 개가 돋움체 12의 **내장 1비트 비트맵**(EBDT, ppem 12)과 0픽셀 차이로 같다. 따라서 GDI는 CreateFont 높이 = ppem의 내장 비트맵을 그린다.
- **호스트 GDI 대조**:
  - 조건: 한국어 Windows 11 26200, PowerShell로 원본과 같은 인자로 CreateFontW, TextOutW (1,1), 32bpp DIB.
  - cp949 17,143자 전부에서 픽셀과 폭(GetTextExtentPoint32)이 모두 같다:
    - 굴림체 12·14: 비트맵 그대로
    - 굴림체 13: 픽셀은 같다. 2바이트 글자 폭만 14(반각 7의 2배)이고, 비트맵의 폭은 12~13이다.
    - `Courier New` 15 + 0x81: GetTextFace가 "굴림"이다. 굴림 15 비트맵과 전부 같다.
  - 실제 게임 문자열 32개 × 4개 크기도 픽셀·폭 모두 같다(13의 폭 14는 다음 글자 위치에도 적용된다).
- **외곽선 blit**(`0x413f70`, `0x414070`):
  - 행 0~14만, 가로 7×(바이트 수+3) 픽셀 안의 잉크만 이웃 8칸 중 색 키 칸을 외곽선 색으로 바꾼다.
  - 복사는 {0,0,799−x,15}를 색 키로 한다. 그 밖의 잉크는 외곽선 없이 복사된다.

## Scope

1. **`tools/shakefmt/font.py`**(표준 라이브러리만 씀)
   - 로컬 `gulim.ttc`를 읽는다. 후보는 `/mnt/c/Windows/Fonts/gulim.ttc`와 `C:/Windows/Fonts/gulim.ttc`, 환경 변수는 `SHAKE2_GULIM_TTC`이다.
   - TTC, name, cmap 4, EBLC(색인 형식 1~5), EBDT(그림 형식 1, 2, 5, 6, 7, 8, 9)를 직접 해석한다. 새 의존성은 없다.
   - 굴림체 12·13·14와 굴림 15의 cp949 전체 글자를 `assets/extracted/font/`에 저장한다: 글자마다 폭·왼쪽·위·너비·높이·비트, 그리고 `index.json`("재배포 금지").
   - GDI 폭을 구워 넣는다. 고정폭(…체) 글꼴의 2바이트 글자는 반각 폭의 2배로 한다.
2. **`tools/tests/test_font.py`**
   - 합성 미니 글꼴로 형식을 해석하는지 확인한다.
   - 실제 `gulim.ttc`가 있으면 문자열 렌더의 해시를 GDI 대조값과 비교한다(글자 데이터는 저장소에 넣지 않음).
3. **`game/scripts/sync-assets.mjs`**: BGM처럼 있으면 복사한다. manifest에 `fonts`를 넣고 `Manifest` 타입을 고친다.
4. **`game/src/client/bitmapFont.ts`**(해석·배치)와 테스트.
5. **`game/src/client/text.ts`**
   - 비트맵이 있으면 GDI처럼 그린다:
     - 작업 표면 (1,1)
     - 원본 외곽선 규칙 그대로
     - 행 0~14 복사
     - 가운데 정렬과 `fitText`는 폭의 합으로
   - 설치될 때 캐시를 비운다.
   - 글꼴 파일이 없거나 글자가 없으면 문자열 전체를 지금의 브라우저 경로로 그린다.
6. **`main.ts`**: 첫 화면 전에 글꼴 로드를 기다린다. 이 로드는 실패해도 거부하지 않는다.
7. **검증**:
   - `tsc`, `vitest`, `pytest`
   - Playwright로 캔버스를 읽어 GDI 덤프와 픽셀을 비교한다(크기마다 하나 이상).
   - 로비·방·옵션·게임 스크린샷
8. **문서**: FIDELITY §6 글꼴·§11 채팅 글자 메모, README(글꼴 동기화), 이 계획의 결과.

범위 밖:
- 16비트 색 양자화
- 굵은 13·Fixedsys(죽은 장면)
- 11px

## Risks

- **2002년 환경과의 차이**:
  - Courier New→굴림 대체와 굴림체 13의 2바이트 폭 14는 현재 Windows 11 GDI에서 확인한 것이다(I). Win98/XP의 글꼴 매퍼도 문자 집합 불일치에 가장 큰 벌점을 주지만, 실기 확인은 없다.
  - 반면 비트맵을 그리는 방식 자체는 Shake1 스크린샷으로 확인했다(V).
- **저작권**: 글꼴 데이터(Microsoft/Sandoll)는 로컬 Windows에서 뽑고 재배포하지 않는다. GDI 덤프도 스크래치에만 둔다.
- **대체 경로**: 글꼴이 없는 환경에서는 지금과 같은 근사로 그린다.

## Results

- **`tools/shakefmt/font.py`**(표준 라이브러리만 씀):
  - 굴림체 12·13·14와 굴림 15의 cp949 17,143자를 모두 뽑는다(빠진 글자 0, 약 3초).
  - 적용한 GDI 규칙은 둘이다: 고정폭 2바이트 폭을 반각의 2배로, 색인 표의 메트릭을 우선으로.
  - 후자는 굴림 15 한글 조합 글리프가 스스로는 14라 하고 색인은 15라 하는데, GDI가 15로 찍기 때문에 넣었다.
- **GDI 대조**(한국어 Windows 11 26200, PowerShell Add-Type으로 CreateFontW/TextOutW, 로컬에서 읽기만 함):
  - 도구 출력이 네 크기 × (17,143자 + 문자열 32개) 모두 픽셀·폭까지 같다.
  - 덤프는 스크래치에만 두고, 저장소 테스트에는 해시만 둔다.
- **테스트**:
  - pytest 99개(합성 미니 글꼴 13개 + 실제 `gulim.ttc` 해시 4개 포함). 색인 메트릭 규칙을 뒤집으면 4개가 실패하는 것을 확인했다.
  - vitest 44파일 557개, `tsc` 통과, `vite build` 통과(dist에 글꼴 포함).
- **Chromium**(Playwright):
  - 앱이 불러온 글꼴로 `outlinedText`·`plainText`를 그려 다시 읽었다. 문자열 32개 × 네 크기 모두 GDI 잉크와 같고, 외곽선은 `0x414070` 규칙과 같으며, 부드러운 픽셀은 0이다.
  - 실제 장면을 다시 읽은 결과:
    - 로비 채팅 (51,377) 굴림체 13: 잉크 406·외곽선 966 전부 기대 색. 1px 옮긴 대조군은 어긋난다.
    - 방 제목 (305,30) 굴림 15: 281·660
    - 방 번호: 61·151
    - 맵 이름 굴림체 12: 197·421
    - 게임 도움말 줄 (외곽선 없음, #ffff9b): 379
    - 옵션 창 (외곽선 없음): 키 이름 "    Z   "·"LCONTROL" 굴림체 13 #ffff00 20·156, 매크로 "안녕 F2" 굴림체 12 110, 친구 "둘"·"접속하지 않음" 55·248
  - 콘솔 오류는 없다.
  - 캔버스 덤프는 스크래치로 옮기고 프로젝트 폴더(`.playwright-mcp`)에서는 지웠다.

## Residual risks

- **Courier New 대체, 굴림체 13의 2바이트 폭 14, 색인 메트릭 우선(I)**:
  - 셋 다 현재 Windows 11 GDI에서 확인한 것이다. 2002년 Win98/XP 실기에서는 확인하지 못했다.
  - 0311 화면 원본 캡처(무손실)가 있으면 V로 올릴 수 있다. 업데이트 안내 이미지 `sh2_up_ex_0*.gif`는 75% 축소본이라 굴림체가 돋움체보다 맞는다는 보조 근거에 그친다.
- **16비트 색**: 글자색은 24비트로 칠한다. 원본은 565로 양자화한다. 외곽선 생략 판정만 565로 비교한다.
- **작업 표면 가장자리**: 0열 잉크의 왼쪽 이웃과 −1행 쓰기는 원본에서는 표면 밖 메모리로 간다. 복원판에서는 버린다(해당하는 글리프 없음).
- **글꼴이 없는 환경**: 지금까지와 같은 브라우저 근사로 그린다. 15는 이제 Courier New가 아니라 굴림을 요청한다.
