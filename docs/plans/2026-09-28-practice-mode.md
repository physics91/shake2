# 쉐이크2 복원: 연습 모드

## Goal

지금 연습 모드는 네트워크 규칙에 혼자 서는 임시판이다. 원본 `shake.exe`의 연습(장면 9)과 같게 바꾼다.
역분석 근거는 `re_work/findings_practice.md`(장면 9 전체), `findings_items_roll.md` §1.9(연습 확률표·미리 놓인 아이템), `findings_items_states.md`(연습 순간이동)와 이 단계의 추가 조사에 있다.

## Scope

| 항목 | 원본 | 근거 |
|---|---|---|
| 맵 | 늘 `practice.MAP`, 맵 선택 없음 | `0x4708d8` |
| 플레이어 | 4명: 더미 3(캐릭터 `rand()%18`, 칸 0/7/14) + 나(칸 97). 위치 (칸X+20, 칸Y+17) | `0x454730`, 표 `0x469b8c`·`0x469bac`, `0x4547e6` |
| 더미 | 입력·AI·폭탄 없음, 서 있기만. 불꽃에 죽고 die4 | `0x407bb0`–`0x407ff0`, `0x407d84` |
| 흐름 | 대기·카운트다운 없음, 서든데스·HURRY·BGM·사탕·패킷 없음. 150초 뒤 곧바로 내 정보 화면(장면 5) | `0x45aec8`, `0x457440`, `0x40622b` |
| 끝 상자 | 더미가 모두 사라지거나 내가 죽으면 표시. 밑에서 게임은 계속, 입력만 막힘. YES 다시 시작, NO 나가기(장면 2) | `0x407b02`, `0x4083be`, `0x458a19`–`0x458b88` |
| Esc 상자 | "종료하시겠습니까?" YES 나가기, NO 다시 시작. Esc로 닫을 수 없음 | `0x461590`, `0x461bc0` |
| 스탯 | 상한 0: 폭탄·화력·속도 증가가 효과 없음 | `0x4511d7`, `0x4511f7`, `0x451217` |
| 아이템 | 벽돌 확률표 `rand()%299`, 미리 놓인 아이템 24개(칸 이웃 8곳 중 첫 빈 칸, 1 px 위) | `0x454d7a`–`0x454e7c`, `0x455000`, `0x455500` |
| 순간이동 | `rand()%3`으로 더미의 캐릭터 번호를 플레이어 번호로 씀(원본 버그) | `0x45c90e` |
| 화면 | 하단 문구 대신 textbox와 마우스 도움말, 오른쪽 패널 이름·메달 없음 | `0x408d21`, `0x4557f0`, `0x40f9a0`(네트워크만) |

화면 세부(패널, 소리 목록, 상자 버튼 그림, F1 도움말, 채팅)는 추가 조사 결과로 정한다.

범위 밖: 원본 0311에 연습으로 들어가는 정적 경로가 없는 문제(§0b)는 복원판 메뉴의 "혼자 연습"으로 대신한다. 내 정보 화면(장면 5)은 연습 설정 화면(캐릭터 선택)으로, 서버 선택(장면 2)은 첫 메뉴로 대응시킨다.

## Approach

- 시뮬레이션: `rules.practice`일 때 `createMatch`가 더미 3명과 내 플레이어를 원본 순서의 난수로 만들고, 곧바로 `playing`에서 시작. 끝 상자 조건은 이벤트로 알림. 시간 초과는 별도 이벤트
- 상자는 연습이 한 PC 전용이므로 클라이언트(`localGame`)가 가짐: 상자가 떠 있으면 입력을 비움. 키보드(←/→, y/n, Enter)와 마우스 클릭 둘 다
- 원본 연습 상자는 그리기 버그로 메뉴 버튼 조각이 보임. 의도한 Shake1 "다시 시작할까요?" 판을 그리고 FIDELITY에 의도적 차이로 적음
- 테스트 먼저, 30 Hz 틱 시간 그대로

## Steps

1. 추가 역분석(줍기·소리·그리기 순서·상자 버튼·F1·채팅)
2. 시뮬레이션: 연습 플레이어 4명, 곧바로 시작, 서든데스·HURRY 없음, 스탯 상한 0, 시간 초과·끝 상자 이벤트, die4
3. 아이템: 연습 벽돌 확률표, 미리 놓인 아이템
4. 연습 순간이동
5. 클라이언트: 연습 설정(맵 선택 없음), 상자 두 종류, Esc, 다시 시작·나가기·시간 초과 이동, 음악 유지
6. 화면: 하단 문구·패널·사탕 등 연습 전용 그리기, textbox 도움말, F1 도움말
7. FIDELITY §11, README, 실제 UI 확인

## Progress

- 1–7단계 완료. 이어서 연습 전용 폭탄(지뢰탄·호박탄·물 계열), 불꽃 종류 2~5와 실명 화면, 연습 아이템 칸, 채팅(편집기 한도·캐럿 깜빡임·말풍선·입력 중 표시)을 넣었다.
- 상자·F1·채팅 중에는 입력 폴링을 건너뛰는(`null` 입력) 원본 동작으로 바꿨다: 걷던 플레이어는 계속 걷는다.
- 실제 UI 확인(2026-09-28, Playwright Chromium): 허수아비 모두 제거 → 끝 상자, y 다시 시작·마우스 NO 나가기, Esc 상자 마우스 NO 다시 시작·키보드 ←+Enter 나가기, 150초 시간 초과 → 설정 화면, 스탯 아이템(폭탄·화력·속도) 줍기 무효, 채팅(한글 IME 조합은 CDP `Input.imeSetComposition`으로 구동, 36바이트 제한, 캐럿 위치·깜빡임, 말풍선 5초, 채팅 중 걷기 지속, 상자 아래 입력 거부). 허수아비 제거와 스탯 아이템 배치는 개발용 `window.shakeMatch`로 위치·아이템을 놓고 폭탄·줍기는 실제 키로 했다.

## Follow-ups

- 글자 렌더러: 원본은 굴림체 비트맵 글꼴(11~14 px)로 그린다. 로컬 `gulim.ttc`의 비트맵(EBDT)으로 글자 그림을 만들면 모든 화면 글자를 원본과 같게 할 수 있다. 글꼴은 원본 자산처럼 로컬 전용이어야 하며 모든 화면에 걸친 변경이라 별도 단계로 한다.
