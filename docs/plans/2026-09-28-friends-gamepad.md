# 쉐이크2 복원: 친구 목록을 서버가 맡게 하기, 조이스틱 저장 시점과 키보드 대체

## Goal

FIDELITY §19의 남은 추정(R/I) 가운데 옮길 수 있는 것을 원본의 역할 분담대로 바꾼다.

1. **친구 목록**
   - 원본은 클라이언트가 보여 주기만 하고, 목록과 결과(−1~−5)는 계정 서버가 정한다.
   - 복원판은 지금 이 브라우저의 `localStorage`에 두고 클라이언트가 결과를 정한다.
   - 이를 서버가 이름별 목록을 두고 결과를 정하도록 바꾼다.
2. **조이스틱**
   - control은 원본처럼 O·초기화 때만 저장한다(지금은 바로 저장).
   - 조이스틱 모드에서 패드가 아직 안 보이면 게임 입력이 비는 문제가 있다. 이때 키보드를 읽는다.
   - 축 늘림 등급을 문서로 올린다.

## Evidence

- **패킷**(`findings_option_input.md` §A.4·§C, 부모가 `0x44bff0`·`0x44c1c0`·`0x44c220`·`0x4458d3`를 다시 확인):
  - C→S 0x63 {}: 목록. 이름을 보내지 않는다.
  - C→S 0x64 {ID}: 추가. 보낼 때 바쁨 커서와 바쁨을 켠다.
  - C→S 0x65 {ID}: 삭제. 보낼 때 바쁨 커서와 바쁨을 켠다.
  - S→C 0x64 {i8 r, 이름}: 창을 닫고 바쁨을 끈다.
    - 1: "☞ %s님이 친구로 / 등록되었습니다", 바쁨, 0x63
    - −1~−5: 표의 문구
    - 0과 그 밖: 조용히
  - S→C 0x65 {r, 이름}: 바쁨을 끈다.
    - r=1이고 이름이 있으면: 문구, 창 닫기, 바쁨, 0x63
    - r≠1: "삭제 실패", 창 닫기
  - S→C 0x63: 목록(성별, 길드, 계급, 이름, 위치)이며, 서버가 12명을 지킨다.
- **조이스틱**(§E):
  - 시작 `0x461900`: control=1이면 조이스틱 초기화, 실패하면 키보드·control 0·저장.
  - 1P·조이스틱 체크는 메모리만 바꾸고 저장은 O·초기화(`0x44d040`)가 한다.
  - 조이스틱 모드에서는 키보드 게임 입력이 멈춘다.
- **데드존**: DirectInput 문서 "Interpreting Joystick Axis Data"의 그림에서 (dmax, ctr)부터 (smax, max)까지가 직선이다. 원본은 포화를 정하지 않으므로 smax = pmax(기본 10000)이다.
- **복원판 확인**: control=1인데 패드가 보이지 않으면 `practiceGame`·`OnlineGame`의 입력이 비어 조작할 수 없다. 브라우저는 페이지에서 패드 단추를 한 번 눌러야 패드를 보여 준다.

## Scope

1. **settings**
   - `SettingsStore.setControl`(메모리만 바꾸고 알림)을 추가한다.
   - `save`는 모두 쓰고, `update`(툴바의 효과음·음악)는 저장된 control을 그대로 둔다.
   - 옵션 창의 1P·조이스틱과 페이지 라디오는 `setControl`을 쓴다. 페이지 문구를 고친다.
2. **입력**
   - 조이스틱 모드에서 패드가 보이면 패드만, 안 보이면 같은 키 설정의 키보드를 읽는다. 저장값은 바꾸지 않는다.
   - 키 도움말 문구를 고친다.
3. **프로토콜 7**
   - C→S: `friends {}`, `add-friend {name}`, `delete-friend {name}`
   - S→C: `friends {friends}`(그대로), `friend-added {result, name}`, `friend-deleted {result, name}`
4. **서버 `FriendStore`**
   - 이름 → 친구 ID 목록(12명 이하)과 "이 서버에 접속한 적 있는 이름"을 기록한다(−4 판정용).
   - 결과 규칙:
     - 빈 ID·없는 ID: −4
     - 자기 자신: −5
     - 중복: −2
     - 12명 초과: −3
     - 저장 실패: −1 → 실행하며 바꿈: 저장을 1초씩 모아 쓰므로 추가 순간에는 저장 실패를 알 수 없다. −1은 "서버가 이름을 더 기억하지 못함"(4096명)에 쓴다.
     - 삭제 대상이 목록에 없음: 0
   - 저장:
     - JSON 파일 하나. 경로는 `FRIENDS_FILE`, 기본값 `game/data/friends.json`(`public/assets` 밖).
     - 임시 파일에 쓴 뒤 이름을 바꾼다.
     - 깨진 파일은 옆으로 옮기고 빈 상태로 시작한다.
     - 이름 수는 상한을 둔다.
   - 테스트 서버는 메모리만 쓴다.
5. **클라이언트**
   - `localStorage` 친구 목록, `readFriends`, `addResult`를 없애고 요청·응답으로 바꾼다.
   - 대상: `optionScreen`(창의 바쁨·닫기·재요청 순서는 원본대로), `optionPanel`, `lobbyView`, `online.ts`
6. **검증**
   - `tsc`, `vitest`, `pytest`
   - 실제 서버와 Chromium 두 페이지로 확인한다: 서로 추가, 위치가 로비에서 "NNN번 방"으로 바뀜, 거절 문구, 삭제, 서버를 재시작해도 목록이 유지됨.
   - 패드는 실제 장치가 없어 `navigator.getGamepads` 스텁(모의)으로만 연결을 확인한다.
7. **문서**: FIDELITY §8·§19, README(프로토콜 7, 서버 재시작, `FRIENDS_FILE`), 이 계획의 결과.

범위 밖:

## Risks

- **서버 규칙은 여전히 R**: 원본 서버 코드는 없다. 결정을 원본이 하던 곳(서버)으로 옮길 뿐이다.
- **이름 기반 신원**: 비밀번호가 없어서 누구나 그 이름으로 들어와 그 이름의 목록을 바꿀 수 있다. 같은 이름으로 동시에 접속하면 목록을 함께 쓴다(서버가 중복 이름을 막지 않음).
- **처음 생기는 서버 영구 자료**: 친구 ID와 접속한 이름을 로컬 파일에 저장한다.
- **패드 확인**: 실제 패드로는 확인하지 못한다(장치 없음, Playwright에 패드 흉내 기능 없음).

## Results

- **조이스틱**:
  - `SettingsStore.setControl`: 1P·조이스틱(캔버스 창과 페이지 라디오)은 장치를 바로 바꾸고 저장은 O·초기화 때만 한다.
  - 툴바의 효과음·음악 저장은 아직 저장되지 않은 장치를 쓰지 않는다.
  - 조이스틱 모드에서 패드가 보이지 않으면 같은 키 설정의 키보드를 읽는다(연습·온라인). 키 도움말이 이를 알린다.
  - 축 늘림은 DirectInput 문서 그림으로 V다.
- **친구 목록**:
  - 프로토콜 7. 서버 `FriendBook`(순수 규칙)과 `friendFile`(JSON, 1초 모아 쓰기, 임시 파일 뒤 이름 바꾸기, 0600, 깨진 파일은 옆으로 옮김, 끌 때 씀).
  - `FRIENDS_FILE`의 기본값은 `game/data/friends.json`이다.
  - 클라이언트의 `localStorage` 목록과 결과 판정을 없앴다. 캔버스 창과 페이지 부분은 보내고 답을 기다린다(물은 쪽만 답을 받음).
- **추가로 막은 것**: Vite 개발 서버가 루트 아래 `data/`를 그대로 내주는 것을 확인했다(200). 그래서 `server.fs.deny`에 넣었다(403). 파일, `.tmp`, `.broken-*`, `/@fs/` 경로 모두 403이다.
- **테스트**:
  - vitest 46파일 576개. 서버 규칙, 파일 저장·복구·쓰기 실패, 프로토콜, 로비, 창 순서, 설정 저장 시점을 다룬다.
  - `tsc`, `vite build`, pytest 99개 통과.
- **기본 경로**: `FRIENDS_FILE` 없이 서버를 켜고 hello 뒤 SIGTERM을 보냈다. `game/data/friends.json`(0600)이 생기고 Vite에서는 403이다. 확인 뒤 지웠다.
- **실제 확인**(Node 서버 + Vite + Chromium 두 페이지, 친구 파일은 스크래치):
  - 페이지 부분 추가: 1, −2, −5, −4(없는 이름), −4(빈 아이디). 문구는 원본 표 그대로다.
  - 방에 들어간 친구의 위치가 "001번 방"으로 바뀐다.
  - 캔버스 옵션 창에서 삭제와 추가: 원본 메시지 상자가 뜨고 목록을 다시 묻는다. 스크린샷은 스크래치에 두었다.
  - 서버를 재시작해도 양쪽 목록이 남는다.
  - 끄기 1초 안의 추가도 SIGTERM에서 저장된다.
  - 375px 페이지에서 키보드로 추가·삭제한다. 포커스는 입력 칸에 남고 가로 넘침은 없다.
  - −3(13번째)과 −1(이름 표가 가득 참)은 단위 테스트로만 확인했고 실제 경로로는 확인하지 않았다.
- **패드**(모의: `navigator.getGamepads`를 페이지 스크립트로 바꿈. 실제 장치 아님):
  - 연습에서 패드가 없을 때 →로 오른쪽으로 움직인다.
  - 패드가 생긴 뒤 스틱 아래와 ←를 함께 누르면 아래로만 움직인다.

## Residual risks

- **서버 규칙과 위치 문구는 R**: 원본 서버 코드가 없다. 판정하는 곳과 순서만 원본과 같다.
- **이름 기반 신원**: 비밀번호가 없어 그 이름으로 들어오는 누구나 그 이름의 목록을 보고 바꾼다.
  - 같은 이름으로 동시에 접속하면 목록을 함께 쓴다.
  - 친구 파일에는 접속한 이름이 최대 4096개 남는다. 공개하면 안 된다(README).
  - 이름 밀어내기: hello는 인증 없이 한 연결에서 여러 번 보낼 수 있다. 한 클라이언트가 초당 120개 제한 안에서 약 35초 만에 새 이름 4096개를 넣을 수 있다. 그러면 목록에 없고 목록도 없는 이름이 모두 잊혀, 접속하지 않은 사람을 추가하면 −4가 나온다(다시 접속하면 풀림). 디스크 쓰기는 1초에 한 번이라 입출력 부담은 없다. 이번 단계에서는 막지 않았다.
- **이전 목록 손실**: 프로토콜 6 때 브라우저에 저장한 친구 아이디는 옮기지 않는다. 옛 `shake2.online.friends` 값은 브라우저에 남지만 읽지 않는다.
- **패드**:
  - 실제 패드로는 확인하지 못했다.
  - 시작 때 조이스틱이 없으면 키보드로 되돌리는 원본 동작은 여전히 옮기지 않았다(R). 브라우저가 패드를 숨기기 때문이다.
  - 패드가 보이기 전 키보드로 움직이는 것은 원본에 없는 동작이다(R).
- **`FRIENDS_FILE`을 루트 안 다른 곳으로 바꾸면** Vite 개발 서버의 차단 목록에 들지 않는다. 기본 경로만 막았다.
