# 쉐이크2 복원: 클라이언트 동작 차이 한 묶음

## Goal

원본 클라이언트 코드로 동작이 확인되는데 복원판에 아직 옮기지 않은 항목(FIDELITY의 R·I 가운데 "옮길 수 있음" 갈래)을 한 묶음 옮긴다.

## Scope

남은 차이를 세 갈래로 나눈다.
- (a) 같게 만들 수 없음: 서버 규칙(서버 실행 파일이 보존되지 않았고 매뉴얼에도 규칙이 없음), 계정 자료, 원본 자체가 실행마다 다른 것.
- (b) 일부러 다르게 둔 것: 사용성 때문에 고른 차이.
- (c) 옮길 수 있는데 아직 안 옮긴 것: 이번 대상.

이번 묶음:
1. 종료 상자: 라운드 결과·최종 결과·2라운드부터의 대기 화면은 매 프레임 종료 상자를 닫음(`0x40fd50`, `0x410560`, `0x4100e0` → `0x443d50`). 복원판은 상자를 열어 둔 채 키를 받음. FIDELITY §15 "종료 상자" 행을 고침.
2. 방장 퇴장 줄: 방 안에서 방장을 바꾸는 패킷은 S→C 0x40뿐(`0x440590` 호출 3곳 중 나머지는 입장·방 만들기). 0x40은 나간 슬롯·방장 바뀜·새 방장을 받아 "★★ %s님이 퇴장하셨습니다 ★★"(`0x46ef34`)를 쓰고 슬롯을 비움. 장면 8에서는 무시(`0x44ab4d`). 복원판은 모든 퇴장에 보통 문구.
3. 방 바쁨 커서(`0x43f0b0`): 조사 결과에 따라 방 안에서 패킷을 보낸 뒤 답이 올 때까지 바쁨 커서.
4. `srand(time)`: 원본은 여러 곳에서 `srand(time(0))`로 다시 시드함. 옮기거나, 옮기지 않으면 FIDELITY §13 "RANDOM 결정" 행(복원판이 "같은 식"이라 적었지만 코드는 `randomInt`)을 바로잡음.
5. 입력 중 표시 보내기 규칙(§15): 상태 패킷을 300 ms 이상 간격, 경기 중, 사라지지 않고 순간이동 비행이 아닐 때만 보냄. 받는 쪽은 살아 있을 때만 받음.

범위 밖: "network problem!"(원본은 P2P 방장 무응답 5초 감시, 복원판은 서버 중심이라 설계 판단이 필요), 서버 규칙 항목들.

UI 변경은 접근성(상태 문구), 375 px, 키보드 경로를 확인한다. 새 의존성 없음.

## Results

- 종료 상자: `closesExitBox`로 라운드 결과·최종 결과·2라운드부터의 대기 화면에서 매 프레임 닫음. FIDELITY §15 "종료 상자" V.
- 방장 퇴장 줄: `ChatKind` `host-leave`, 서버 `leave`가 방장이 바뀔 때 보냄, 클라이언트 "★★ %s님이 퇴장하셨습니다 ★★". §13 I.
- `srand(time)`: `MatchState.clockMs`와 `srandTime`으로 원본이 다시 시드하는 곳(라운드 시작의 출발점·숨은 아이템, 소환, 방 START의 RANDOM 맵·음악)을 옮김. 시뮬레이션은 결정적으로 남음. 출발점 0은 원본도 뽑지 않음(새 V).
- 방 바쁨 커서: 조사 결과 방에서 켜는 곳은 슬롯 열기·닫기, 강퇴, `/ban`뿐이고 입력 잠금 없음. 복원판에 있는 슬롯 열기·닫기만 옮김. `CursorAnim.set`이 원본처럼 프레임만 처음부터(마지막 프레임 시각 유지). `endsBusy`가 슬롯·팀 변경만 끔으로 봄.
- 입력 중 표시 보내기: `typingPacketDue`와 서버 `sendTypingFlags`. 경기 틱마다 사람별 300 ms 규칙, 비행·사라짐 중 멈춤, 살아 있을 때만 받음, 카운트다운에는 없음.
- 검증: vitest 609 통과(48 파일), `tsc` 0, `npm run build` 성공.
- Chromium(Playwright, 실제 서버와 vite, 두 브라우저 문맥): 서버를 SIGSTOP으로 멈춘 채 방장이 빈 슬롯을 누르면 시계 커서가 뜨고 1.2초 뒤에도 애니를 돌며 유지, SIGCONT 뒤 슬롯이 바뀌며 화살표로 돌아옴. 손님이 경기 중 Esc로 연 종료 상자는 라운드가 끝나자 결과·대기 화면에서 사라지고 다음 카운트다운에도 없음. 방장이 방을 나가자 손님 기록에 "★★ 방장님이 퇴장하셨습니다 ★★", 손님이 방장이 됨. 375 px에서 가로 넘침 없음(scrollWidth = clientWidth), DOM 슬롯 단추로 키보드 열기·닫기 됨. 두 문맥 모두 `shake2.music` 없음. 캔버스 커서는 페이지 스크린숏에 잡히지 않고 스크린숏 뒤에는 커서가 사라져 있어(스크린숏이 포인터를 캔버스 밖으로 보는 것으로 추정), 확인마다 마우스를 1px 움직인 뒤 캔버스를 복사해 봄.

## Residual risks

- 방 바쁨 커서를 끄는 조건은 복원판의 방 갱신이 원본 패킷 종류를 구분하지 않아 슬롯·팀 차이로 추정함. 같은 갱신에 슬롯 변경과 준비 변경이 섞이면 원본과 같게 끔. 서버 거절 때 끄는 것은 원본의 실패 0x45에 대응시킨 것.
- 원본은 커서가 장면 사이에 하나라 연결이 끊기면 바쁨 커서가 목록 화면까지 남음(`0x460e50`). 복원판은 화면마다 커서가 따로라 남지 않음.
- 입력 중 표시를 보내는 시각의 위상: 원본은 사람마다 자기 GetTickCount, 복원판은 경기 시작 틱 기준.
- `clockMs`(서버 벽시계 ms)가 상태에 실려 클라이언트로 감. 시각 정보라 민감도는 낮음.

### 둘째 묶음 남은 위험

- 귓말 서버 규칙(이름 일치, 같은 이름이 여럿이면 먼저 인사한 사람, 없을 때 조용히 버림, 귓말 켜짐 기본)은 원본 서버 코드가 없어 정한 것.
- 원본 귓말의 보낸 사람 칸은 10바이트까지 읽음. 복원판 이름은 12자까지라 더 길 수 있음.

- `/w`와 채팅이 같이 쓰는 2000 ms, `/users`의 5초는 vitest로만 확인함. Chromium에서는 보내기 간격을 2초 넘게 두어 버려지는 경우를 지나지 않음.

### 넷째 묶음 남은 위험
