# 비밀방과 암호 창

## Goal

로비의 비밀방을 0311 코드대로 옮긴다: 방 만들기 창의 비밀방 칸과 암호 칸, 방 목록의 비밀방 문 아이콘, 비밀방 줄을 누르면 뜨는 암호 창, 암호가 틀렸을 때(입장 답 3) 다시 뜨는 암호 창. 서버(복원판)가 방 암호를 두고 입장 때 확인한다. 이어서, 앞 작업에서 남긴 장면 5 캐럿 버그(바이트 캐럿을 다시 바이트로 바꿈)를 따로 고친다.

## Scope

- 클라이언트: `lobbyScreen.ts`, `lobbyLayout.ts`(좌표·그림), `lobbyView.ts`(숨긴 양식), `online.ts`(새 답 처리).
- 서버: `protocol.ts`(메시지·요약·버전 10), `lobby.ts`(암호 저장·확인·시도 간격), `room.ts`(요약의 비밀 표시).
- 문서: FIDELITY §14 줄들, README "구현하지 않은 것".
- 범위 밖: 강조(아이템 6)·베팅(아이템 7) 칸(보내는 곳이 없음), 계정 아이템 전반.

- 방 줄 클릭 `0x459e06`: 게임 중 → "이미 시작 되었습니다.", 비밀방 대기 중 → 암호 창 `0x42f500`, 아니면 바쁨 + 입장(빈 암호).

- 그리기 `0x42ea30`: new_basicwindow (2,2)-(240,181)→(191,151), 자물쇠 new_button (1,77)-(30,107)→(242,206), 글자 new_button2 (178,204)-(281,219)→(278,215), '*' (248,242) F13 #c8e5fd, OK (198,292)-(229,323) 눌림 new_button2 (1,147)-(33,179), 취소 (385,292)-(416,323) 눌림 (34,146)-(66,178), 캐럿 기준 (248,242).
- OK 클릭·Enter `0x4599xx`, `0x45fe06`: 빈 암호 → "비밀번호를 입력하세요"(창 그대로), 아니면 바쁨 → 입장 `{방, 암호}` → 창 닫음. 취소·Esc → 닫음. 풍선: 칸 "비밀번호 입력창", OK "입력 확인(enter)", 취소 "취소 버튼(esc)".
- 입장 답 3 `0x444ffd`: 메시지 없이 암호 창을 다시 엶(빈 칸), 바쁨 끔.
- `/go n` `0x446747`: 빈 암호로 입장을 보냄. 비밀방이면 답 3으로 암호 창.
- 비밀 값(+0x28)은 방 목록 그리기(문 아이콘 5)와 방 클릭에서만 읽힘. 대기실에는 표시 없음.

## Approach

- 아이템 5는 상점이 없어 모두 가진 것으로 본다(R, 캐릭터 20명과 같은 이유).
- 프로토콜 10: `create-room`에 `password`(10바이트), `join-room`에 `password`(15바이트), `RoomSummary.secret`, 새 S→C `join-password {code}`(답 3). `join-number`(`/go`)는 원본처럼 암호를 보내지 않음.
- 서버: 암호가 비지 않으면 비밀방(원본 서버 규칙은 미상: I). 입장은 암호가 틀리면 `join-password`. 암호는 요약·방 정보·방 상태 어디에도 싣지 않고 로그에 남기지 않는다. 틀린 암호는 500 ms 뒤에 `join-password`로 답하고 그동안 그 연결의 암호는 보지 않음(복원판 추가, 추측 늦추기; 정직한 클라이언트는 답을 기다리는 동안 잠겨 있어 잘못 거절되지 않음). 빈 암호는 바로 답함.
- 클라이언트: 팝업 "password" 추가, 대상 방 코드를 기억. `join-password`를 받으면 그 방 코드로 암호 창을 다시 연다.
- 숨긴 DOM: 만들기 양식에 비밀방 체크와 암호 칸, 비밀방 줄 버튼은 캔버스 클릭과 같은 길(암호 창).

## Verification

- 단위 시험(서버·프로토콜·레이아웃), 타입 검사, 빌드.
- Chromium 두 컨텍스트 + 실제 `npm run server`(시험용 친구 파일): 비밀방 만들기, 목록의 문 아이콘, 틀린 암호 → 빈 암호 창 다시, 빈 암호 → 메시지, 맞는 암호 → 대기실, `/go n` → 암호 창.
- 보안: 로비·방 메시지 어디에도 암호가 없는지(WebSocket 프레임 확인), 서버 로그에 없음.

## Residual risks (작성 시점)

- 원본 서버의 비밀방 규칙(빈 암호, 검사 순서)은 미상이라 추정.
- 암호는 평문 WebSocket(`ws://`)으로 간다. LAN·로컬용이며, 공개 서버는 `wss://` 프록시가 필요.

## Results (2026-09-30)

- 단위 시험: vitest 54 파일 688개 통과(서버 비밀방 6개, 프로토콜 1개, 레이아웃 5개 추가). `tsc --noEmit`, `vite build` 통과. 도구(`tools/`)는 바꾸지 않아 pytest는 돌리지 않음.
- Chromium(Playwright MCP 브라우저의 새 컨텍스트 셋) + 실제 `node src/server/main.ts`(시험용 친구 파일) + vite 프록시:
  - 방장: 방 만들기 창에서 자물쇠 아이콘 → 체크·PASSWORD·칸이 그려지고 편집기는 제목에 남음, 칸 클릭으로 암호 입력('****'), Tab이 제목↔암호를 오감, Enter로 비밀방 생성.
  - 손님: 목록 줄의 잠긴 문 아이콘, 줄 클릭은 아무것도 보내지 않고 암호 창(풍선 "비밀번호 입력창"), 빈 OK → 메시지 상자(창은 그 아래 숨음), 틀린 암호 → 약 0.55초 바쁨 커서 뒤 빈 암호 창, 맞는 암호 → 대기실(방장 쪽 2명).
  - 구경꾼: `/go 1`, 숨긴 참가 버튼(요청 없이 창), 방 코드 양식 모두 암호 창, Esc는 창을 닫고 채팅으로. 숨긴 만들기 양식의 비밀방 체크·암호(10바이트 자름, 체크를 끄면 지움).
  - 암호는 보낸 본인의 프레임에만 있고 세 컨텍스트가 받은 어떤 프레임에도, 서버 로그에도 없음. 페이지 오류 없음.
  - 375 px: 캔버스만 보이고 가로 스크롤 없음. 기본 컨텍스트의 `shake2.music`은 null.
- 가짜로 둔 것: 없음(실제 서버·WebSocket·브라우저). 계정·아이템 서버가 없어 아이템 5는 모두 가진 것으로 봄(R).
- 장면 5 캐럿: `view()`의 캐럿(이미 cp949 바이트)을 글자 위치로 보고 다시 바이트로 바꾸던 세 곳(닉네임·인사말·비밀번호 칸, 옵션 쪽 매크로 줄, 랭킹 검색 칸)을 고침. Chromium 새 컨텍스트에서 캔버스 픽셀로 확인: 고치기 전 "시|험가"(2바이트)의 캐럿이 x 154가 아니라 168(4바이트 자리), 고친 뒤 "시험|가x"(4바이트)의 캐럿이 x 168(140 + 7 × 4).
