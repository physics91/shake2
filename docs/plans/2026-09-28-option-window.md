# 쉐이크2 복원: 옵션 창(장면 13)과 옵션이 쓰이는 곳

## Goal

로비 리모컨의 옵션 버튼이 원본처럼 옵션 창(장면 13)을 열게 한다. 창에서 정한 값(배경음악, 효과음, 풍선 도움말, 조작 장치, 게임 키 세 개, 단축 메시지 F2~F10, 친구 목록)이 원본과 같은 곳에 적용되게 한다.

지금은 다음과 같다.
- 옵션 버튼은 리모컨만 닫는다(FIDELITY §14 R).
- 풍선 도움말은 늘 켜져 있다(§13·§14 R).
- 효과음·음악은 게임 화면 툴바에서만 켜고 끈다.
- 게임 키는 고정되어 있다(`SOLO_KEYS`).
- 채팅 매크로는 없다(§13·§14·§15 R).

## Scope

근거:
- `re_work/findings_option_draw.md`(그리기)
- `re_work/findings_option_input.md`(입력·친구·매크로·조작)
- 부모가 직접 확인한 주소:
  - 창 위치: `0x420f1c`
  - 레지스트리 루프가 CM1..CM10을 모두 도는 것
  - 매크로 호출: `0x461a50`–`0x461bac`. 버퍼 `0x4938bc`는 `0x418cd0(1)`이 빈 문자열(`0x470af8`)로 채우므로 채팅에 들어가는 것은 매크로 글뿐이다.
  - 옵션을 열 때 순서(`0x459ab3`–`0x459ad7`): 리모컨 닫기 → 채팅 닫기 → 바쁨 커서(`0x43f0b0(1)`) → 바쁨(`0x441f60`) → C→S 0x63
  - 키 바꾸기 폴링의 충돌 규칙(`0x40218e`–`0x402268`)
  - 메시지 상자 버튼 풍선이 PHELP를 따르는 것(`0x443947`)
  - 장면 7에서만 메시지 상자 타이머가 매 프레임 다시 잡히는 것(`0x44378c`)

범위:
1. **옵션 저장소**(레지스트리 대신 이 브라우저의 `localStorage`, R)
   - `SoundOpt` 비트: 효과음·음악. 기존 `shake2.effects`/`shake2.music` 키를 그대로 쓴다.
   - `PHELP`
   - `CM1`..`CM10`: 36바이트 cp949
   - `Key1`..`Key3`: DIK. 값이 0이거나 잘못되었으면 기본값 0x39/0x1d/0x2c.
   - `control`: 0 또는 1
   - 게임 화면 툴바의 효과음·음악 버튼도 같은 값을 읽고 쓴다.
2. **옵션 창 그리기**(원본 좌표·그림 그대로)
   - 로비 일부 밑그림
   - new_option (66,80)
   - 매크로 편집 강조, 매크로 글(12바이트 줄바꿈 3줄), 매크로 캐럿(13행, 500/250 ms)
   - 체크 표시 5개
   - 키 바꾸기 막대, 키 이름(원본 이름표 137개, F11이 "F14"로 보이는 어긋남 포함), GESTURE "D"
   - 친구 목록 12줄
   - hover·눌림 그림
   - 친구 창
   - 풍선 도움말(확정된 PHELP를 따름)
   - 그 위에 메시지 상자와 커서. "ver."는 없다.
3. **옵션 창 입력**(원본 순서)
   - 뗄 때 판정 순서: 친구 창 → O → 초기화 → X → 체크 3개 → 키보드·조이스틱 → 키 칸 3개 → 매크로 칸 → 친구 줄 → 그 밖
   - Enter·Esc·F1
   - 바쁨(열 때 목록 답까지 클릭·Esc 무시)
   - 키 바꾸기 모드: 매 프레임 폴링, DIK 2..0x8c 오름차순 첫 키. D는 거절 메시지. 다른 칸과 겹치면 두 번의 폴링에 걸쳐 서로 바뀐다. 모드는 저절로 끝나지 않는다. 키보드 모드에서만 동작한다.
   - 매크로 편집: 37 한도, 실시간 반영(IME 조합 포함)
   - O(적용·저장, 음악을 끄면 곡을 멈춤, 켜도 다시 틀지 않음)
   - 초기화(모두 기본값·저장, 창은 열린 채. 조작 장치는 그대로)
   - X·Esc(되돌리고 닫기. 이미 바꾼 장치와 초기화는 되돌리지 않음)
   - 닫으면 로비와 채팅을 다시 연다.
4. **친구 목록**(계정 서버가 없어 R)
   - 친구 아이디는 이 브라우저에 12개까지 저장한다. 인사말·아이디 체크와 같은 방식이다.
   - 서버에 새 메시지 `friends {names}`를 보내면 `friends {friends: {name, location}[]}`로 위치를 답한다.
     - 로비에 있으면 채널 이름, 방에 있으면 "%03d번 방", 접속하지 않았으면 빈 문자열이다. 빈 문자열이면 원본처럼 "접속하지 않음"을 그린다.
     - 원본 위치 문구는 서버 것이라 미상이다.
   - 추가·삭제 결과 문구는 원본 표를 따른다.
     - 자기 아이디 −5, 이미 있음 −2, 12명 −3, 빈 아이디 −4(I)
     - 성공하면 "☞ %s님이 친구로 / 등록되었습니다" 또는 "☞ %s님이 친구목록에서 / 삭제 되었습니다". 이어서 목록을 다시 요청하고 답이 올 때까지 바쁨이다.
   - 10바이트를 넘는 아이디는 조용히 닫는다(원본대로).
   - 성별 아이콘은 그리지 않는다(로비 사용자 목록과 같은 R). 길드는 0, 계급은 1.
5. **풍선 도움말 옵션**
   - 로비·리모컨·방 정보·방 만들기, 내정보 창, 대기실, 옵션 창, 메시지 상자 버튼의 풍선이 확정된 PHELP를 따른다.
6. **게임 키**
   - 연습(장면 9)과 온라인 경기(장면 8)의 폭탄·공격·회피 키가 옵션의 DIK를 따른다(DIK → `KeyboardEvent.code` 표). 방향키는 원본처럼 고정이다.
   - 키 도움말 문구도 옵션을 따른다.
   - 한 PC 대전(`VERSUS_KEYS`)은 복원판 추가 기능이라 그대로 둔다.
7. **조작 장치(조이스틱)**
   - 조이스틱은 Gamepad API로 옮긴다. 첫 번째 패드의 축 0·1을 ±0.5 기준으로 읽는다(원본 −10..10 범위의 ±5와 같음). 단추 0은 폭탄, 2는 공격, 1은 회피다.
   - 조이스틱 모드에서는 키보드 게임 입력을 읽지 않는다.
   - 창의 조이스틱 칸을 누르면 패드가 보이지 않을 때 "조이스틱 초기화 에러"를 띄운다.
   - 시작할 때 키보드로 되돌리는 원본 동작은 옮기지 않는다(R). 브라우저는 페이지를 연 뒤 패드 단추를 눌러야 패드를 보여 주기 때문이다.
8. **단축 메시지(F2~F10)**
   - 로비(장면 4, 창이 없을 때), 대기실(장면 7, 목록이 닫혀 있을 때), 경기·연습(장면 8·9, 늘)에서 쓴다.
   - F 키를 누르면 채팅을 빈 편집기로 열고 매크로 글을 넣는다. 보내지는 않는다.
   - 예·아니오 상자가 떠 있으면 F2~F9는 무시되고 F10은 무시되지 않는다.
   - F2~F10의 브라우저 기본 동작은 막는다.
9. **접근성**(복원판 추가)
   - 로비 페이지 조작에 "옵션" 부분을 둔다: 체크 3개, 조작 장치, 키 세 개(고르기 목록, D 없음, 겹치면 한 번에 서로 바뀜), 단축 메시지 9칸, 초기화·저장, 친구 목록과 추가·삭제.
   - 캔버스 창의 열기·닫기·메시지는 보이지 않는 상태 문구로 알린다.

범위 밖:
- 랭킹 창(장면 12)
- 2P·기본정보공개: 원본도 동작 없이 풍선만 있다.

## Approach

- **새 모듈**(테스트 먼저):
  - `dik.ts`: DIK↔`code` 표(2..0x8c), 원본 이름표 `0x46ded4` 137개(TAB 포함 원문), `keyName`
  - `options.ts`: 옵션 모델, 기본값, 검증하며 읽기, 저장. 저장소는 인자로 받아 테스트한다.
  - `optionLayout.ts`: 좌표, 뗄 때 판정, 풍선 표, 매크로 줄바꿈과 캐럿
  - `optionWindow.ts`: 장면 13 상태 기계. DOM·캔버스 없이 호스트 콜백으로 적용·닫기·메시지·장치 전환·친구 요청을 한다.
  - `friends.ts`: 친구 아이디 저장과 추가·삭제 판정
  - `macro.ts`: 장면별 F 키 판정, 매크로 글
  - `gamepad.ts`: 패드 → `InputFrame`
- **로비 통합**
  - `lobbyScreen.ts`에 `popup = "option"`을 둔다. 그리기와 입력은 `optionScreen.ts`로 넘긴다.
  - 로비 일부 밑그림(`drawMyInfoScene` 앞부분)은 공용 함수로 뺀다.
  - 매크로 편집기와 친구 아이디 편집기는 `ChatLine`(한도 37·11)을 쓴다.
  - 누른 키는 로비 화면이 `code` 집합으로 들고 매 프레임 DIK로 바꿔 폴링한다.
- **서버**
  - `protocol.ts`에 `friends`를 추가하고 검증한다(이름 12개 이하, 각 64자 이하, `sanitizeName`). `PROTOCOL_VERSION`을 6으로 올린다.
  - `lobby.ts`가 이름으로 접속자를 찾아 위치를 답한다. 로비에 들어온 순서의 첫 일치를 쓴다.
- **위협 메모**
  - 새 메시지는 이름 목록을 받아 그 이름의 접속 위치를 알려 준다.
    - 로비 사용자 목록과 방 정보(`room-info`)로 이미 누구에게나 보이는 정보라 노출이 늘지 않는다.
    - 입력은 크기를 제한하고 검증하며(최대 메시지 4096바이트는 그대로), 처리는 이름 12개에 비례한다.
  - `localStorage` 값은 읽을 때 검증한다(매크로 cp949 36바이트, DIK 범위, control 0·1).
  - 새 의존성은 없다.

- 검토 뒤 고친 것: 캔버스 창의 키 바꾸기가 페이지 옵션 칸에 친 키까지 가져갔다. 페이지 칸에 포커스가 있으면 창이 키를 받지 않고, 창을 누르면 페이지 칸의 포커스를 푼다(Chromium에서 확인).
- 음악 끄기: O·초기화·툴바 모두 `settings.listen` → `SoundBank.setMusic(false)` → `stopMusic()`으로 재생 중인 곡을 멈추고, 켤 때는 다시 틀지 않는다(코드 확인. 실제 소리 출력은 헤드리스라 듣지 못함).

## Residual risks

- 실제 게임패드로는 확인하지 못했다(가짜 `getGamepads`만). 축 늘림(데드존 뒤 −10..10)은 추론(I)이다.
- 친구 위치 문구와 결과 판정은 계정 서버가 없어 재구성(R)이다. 친구 아이디는 브라우저마다 따로 저장된다.
- 이 PC에는 굴림체가 없어 대체 글꼴로 그려진다("☞"가 안 보이고 "니"가 벌어져 보임). Windows 굴림체 환경에서는 확인하지 못했다.
- IME(한글 조합) 입력은 Playwright의 `keyboard.type`(조합 없는 입력)으로만 확인했다.
- 로비 페이지의 폼 칸에 포커스가 있을 때는 F2~F10 기본 동작(F5 새로고침)을 막지 않는다(캔버스·게임 쪽에서만 막음).
- 캔버스 창이 열린 채 페이지 옵션 부분에서 저장하면, 창은 열 때의 값을 들고 있어 나중의 창 O가 덮어쓴다(나중에 저장한 쪽이 남음).
