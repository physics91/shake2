# 쉐이크2 복원: 칸 점유 비트(§9)와 폭탄 목록 순서(§4) 확정

## Goal

FIDELITY §9 "칸 점유"의 남은 추정(비트를 지우는 시점)과 §4 "처리 순서"의 추정(목록에 붙는 순서)을 원본 코드로 확정한다. 원본과 다르게 계산하는 부분은 복원판을 고친다.

## Scope

근거(원본 `shake.exe`):

| 항목 | 내용 |
|---|---|
| 한 프레임 순서 | 폭탄 목록 처리(`0x406524`–`0x407a67`, 네트워크 `0x409…`) → 모든 칸의 점유 비트 지움(`0x45e9a0`: 연습 `0x407b6c`, 네트워크 `0x40a952`) → 플레이어 루프(갱신 뒤 비트 켬 `0x45e920`) |
| 켜는 위치 | 허수아비·원격은 자기 위치. 로컬은 정적 위치 `0x4929a4`: 연습에서는 허수아비마다 자기 위치로 덮어쓰고(`0x407fd2`, `0x407e53`) 로컬 사망 시작에만 로컬 위치(`0x40829c`). 네트워크에서는 갱신 전 로컬 위치(`0x40af70`) |
| 루프 순서 | 연습: 슬롯 순(허수아비 0–2, 나 3), 나도 루프 안(`0x407ff5`). 네트워크: 원격을 슬롯 순으로 한 뒤 로컬을 마지막에(`0x40adfb`) |
| 이동 중 | 충돌 이동(`0x450230`)이 끝난 칸이 `+0x184`와 다르면 옛 칸 비트를 끄고 새 칸 비트를 켬(`0x4504b6`·`0x450654`·`0x4507f9`·`0x451021`). `+0x184`는 충돌 이동 프레임마다 갱신(`0x452b93`), 생성자에서 0(`0x461f02`) |
| 사라짐 | 연습: 사망 애니가 끝난 프레임에도 비트를 켬(`0x407f4d`→`0x407fe8`, `0x4083ad`→`0x40840a`). 네트워크: 슬롯 비트를 모두 지우고 켜지 않음(`0x45e8a0`: `0x40ad4d`, `0x40b7be`) |
| 불꽃 끝 | 불꽃이 꺼질 때(`0x40e510`, 연습 `0x407277`, 네트워크 `0x40a0f1`) 가지 칸마다 폭탄 주인의 점유 비트를 끔(중심 칸은 폭탄 비트만). 핵은 목록 칸이 아니라 반복 번호를 칸으로 써서 칸 0…k−1의 비트를 끔 |
| 읽는 곳 | 구르는 폭탄 `0x40e430`, 직격탄 `0x4170b0`·`0x416f00`, 차기 `0x450906`·`0x4509cf`, 던진 폭탄 `0x40ddc0`(움직임 ≥ 5라 늘 통과), 운반 바닥 `0x417110`(이 판본 맵에 없음) |
| 목록 추가 | `0x441de0`이 마지막 노드 뒤에 붙임. 설치 `0x458344`, 스페셜 `0x457a2d`, 원격 `0x457e99`·`0x45872d` |

복원판에 넣을 것:
- 폭탄 처리는 지난 플레이어 루프의 비트를 보므로, 연습에서 사망 애니가 끝난 플레이어는 그 틱의 나머지와 다음 틱 폭탄 처리까지 칸을 막는다(네트워크는 바로 빠짐).
- 불꽃 끝이 만든 "주인이 안 보이는 칸"은 같은 폭탄 처리에서 뒤에 오는 폭탄에게만 보이고, 플레이어 루프 시작에 사라진다.
- 두 목록 모두 `updatePlayers` 시작에서 비운다(= `0x45e9a0`). 라운드 시작에도 비운다.
- 연습 로컬의 비트는 정적 위치(보통 마지막 허수아비 칸)와, 그 루프에서 칸을 넘어 들어온 칸에 둔다(`MatchState.localMark`). 로컬 자기 갱신 중(차기 검사)에는 아직 켜지지 않았다.

범위 밖:
- 네트워크 원격 플레이어의 위치 패킷(`0x45d300` → `0x45e770`)과 "로컬을 마지막에" 순서: 서버가 모든 플레이어를 한 번에 진행하는 복원판에서는 "다른 플레이어의 현재 칸"이 대응물이다(I로 기록).
- 슬롯 8(비트 18): `al`로 만들어 켜질 수 없지만 방은 6슬롯이라 영향 없음.

## Results

- **확인한 근거**:
  - 연습 루프(`0x407b92`–`0x408905`)에서 사라지지 않은 플레이어는 모두 켬 호출(`0x407fe8`, `0x40840a`)에 닿는다. 빠지는 길은 사라짐 검사(`0x407bdd`, `0x408014`)뿐이다.
  - 핵 결함은 세 사본(연습 `0x407604`, 네트워크 `0x40a472`, `0x40e510`의 `0x40e8a0`)이 모두 같다. `0x40e510`은 TNT 이동에서만 불려 핵 분기에 닿지 않는다.
  - 핵 칸 목록(`+0x58`, −1로 끝, 최대 25)은 `0x417860`이 통과나 마지막을 준 칸만 담는다. 복원판 `nukeCells`와 같아 k = `fireCells.length`다.
  - 폭탄 목록은 `0x441de0`이 끝에 붙인다. 복원판 `state.bombs.push`와 같다(§4 추가 순서 I → V).
- **복원판 변경**:
  - 연습에서 사망 애니가 끝난 플레이어는 그 틱의 뒤 플레이어와 다음 틱 폭탄 처리까지 칸을 막는다.
  - 불꽃이 꺼지면 가지 칸(핵은 칸 0…k−1)에서 주인이 같은 처리의 뒤 폭탄에게 보이지 않는다.
- **불꽃 끝 겹침(§4 I → V)**:
  - 한 폭탄의 불꽃 분기는 쓰기(`0x406a6b`–`0x406e8c`) → 진행(`0x406f5f`–`0x40726c`) → 끝 순이다. 복원판 `burnFire`와 같은 순서다.
  - 끝에서 쓰는 타일 +2 = −1(벽돌 번호)은 벽돌 비트가 켜진 칸에서만 읽히거나 닿지 않는 코드(`0x441ca0`)에서만 읽혀 보이는 차이가 없다.
- **서든데스와 부서지는 벽돌(새로 찾음)**:
  - 원본은 닫힌 칸 전부를 매 프레임 다시 처리한다.
  - 벽돌 취소는 벽돌 비트가 켜졌을 때만 한다(`0x401593`). 그래서 이미 부서지는 중인 벽돌은 블록 위에서 끝까지 부서지고 숨은 아이템을 내놓는다(`0x401890`). 그 아이템은 다음 프레임에 지워진다(`0x4016c7`).
  - 복원판은 부서지는 벽돌도 바로 취소하고 아이템을 처음 한 번만 지웠다. 지금은 원본처럼 부서짐이 이어지고 아이템은 한 틱만 보인다.
- **연습 로컬의 점유(새로 찾음)**:
  - 로컬의 켬(`0x40840a`)은 함수 정적 위치 `0x4929a4`를 쓴다. 쓰는 곳은 허수아비 갱신 끝(`0x407fd2`, 사망 시작 `0x407e53`)과 로컬 사망 시작(`0x40829c`)뿐이다. 루프 앞 쓰기(`0x407ad3`)는 늘 꺼진 `+0x26d`에 걸려 있다(`+0x26c`를 쓰는 곳은 초기화 `0x40cf0c`뿐).
  - 그래서 로컬의 비트는 사라지지 않은 마지막 허수아비 칸에 켜지고, 자기 칸에는 칸을 넘어 들어온 루프에만 켜진다.
  - 복원판 결과: 로컬이 찬 폭탄은 마지막 허수아비 칸으로 굴러 들어가고, 직격탄은 그 칸에서 터지며, 로컬과 같은 칸의 허수아비는 로컬의 폭탄을 막는다.
- **벽돌 칸 0**: 벽돌 갱신은 칸 번호 ≤ 0을 건너뛴다(`0x4018bd`). 16개 맵 JSON 모두 칸 0에 벽돌이 없어 영향이 없다.
- **검증**:
  - 1차: `tsc` 오류 0, `vitest` 592개 통과(48파일, 새 테스트 8개), `vite build` 성공. Chromium 연습 화면에서 폭발 → 불꽃 끝 → 내 사망 → 끝 상자까지 진행했고 콘솔 오류는 없었다.
  - 2차(연습 로컬): `tsc` 오류 0, `vitest` 598개 통과(새 테스트 6개), `vite build` 성공.

## Residual risks

- **허수아비가 모두 사라진 뒤(R)**: 원본은 그리기 코드가 정적 위치를 조건에 따라 덮어쓸 수 있다(`0x40883a`, `0x4089ab`, `0x408cd7`). 그 뒤 로컬 비트의 위치는 확인하지 않았다. 복원판은 마지막 허수아비의 마지막 위치를 유지한다. 이때는 끝 상자가 이미 떠 있다.
- **`+0x184` 초기값(I)**: 생성자는 0으로 두지만, 연습을 다시 시작할 때 구조체를 새로 만드는지는 확인하지 않았다. 복원판은 연습마다 0에서 시작한다(첫 이동 한 프레임만 영향).
- **`0x450230`의 다른 출구**: 비트를 갱신하지 않고 끝나는 길(차기 `0x450ad4`·`0x450cca`, 폭탄에 막힘 `0x450d09`–`0x450dbd`)은 위치가 바뀌지 않는 길로 보고, 복원판은 이동 뒤 칸만 비교한다.

- **네트워크 원격 점유(I)**: 원본은 원격 플레이어의 점유를 위치 패킷으로 옮긴다. 복원판은 서버가 모두 진행하므로 "다른 플레이어의 현재 칸"으로 대응한다. 원격 폭탄이 목록에 붙는 시점도 같은 이유로 다르다.
- **브라우저 재현 안 함**: 점유 쪽 새 동작은 한두 프레임 창이고, 서든데스 위에서 벽돌이 계속 부서지는 모습(최대 약 1초)은 서든데스 시점을 맞춰야 해 브라우저에서 눈으로 보지 않았다. 둘 다 유닛 테스트로만 확인했다. 그리는 순서는 서든데스 칸 → 벽돌(`renderer.ts`)이라 부서지는 벽돌이 블록 위에 그려진다.
- **스냅샷 크기**: 스냅샷 JSON에 배열 두 개(대개 비어 있음)가 늘었다. 프로토콜 번호는 바꾸지 않았다. 클라이언트와 서버는 같은 `MatchState` 타입을 쓴다.
