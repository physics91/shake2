# 쉐이크2 복원: 원본 코드로 풀 수 있는 추정 항목 정리(대기 화면·상자 소리·다시 시작·라운드 시작 고리)

## Goal

FIDELITY에 추정(I)이나 재구성(R)으로 남은 항목 가운데, 원본 실행 파일을 더 읽으면 확정할 수 있고 화면이나 소리에 드러나는 것을 확정하고, 원본과 다르면 복원판을 고친다.

## Scope

1. §6 대기 화면: 2라운드부터 결과 화면 위에 상태 글이 겹치는 것(R → 재현).
2. §13 대기실 EXIT 상자의 키 무음(I), §15 경기 종료 상자·§11 연습 상자의 키 소리.
3. §11 연습 다시 시작이 말풍선과 채팅 줄을 지우는지(I).
4. §10 라운드 시작 고리가 원본 화면에 보이는지(I), bomb8 틱당 한 번(I).

범위 밖: 서버·계정 자료에 달린 R 항목, 하드웨어에 달린 I 항목(16비트 표면 단계에서 정리).

## Evidence

- **대기 화면**(`0x4100e0`): 2라운드부터 배경 없이 줄을 다시 그리고 상태를 (339, y+21)에 찍음.
  - 라운드 끝(`0x44ea40`, `0x44f110`)이 모든 `+0x80`을 0으로 지워, 결과 화면(`0x40fd50`)의 손님 상태는 "준 비 중 ..".
  - 패킷 B(`0x447fa0`)·C(`0x444654`)가 `+0x80` = 2로 만들면 대기 화면은 "준 비 완 료   "(`0x46af54`, 공백 3칸)을 같은 자리에 찍음.
- **상자 키**: 아래 셋 모두 효과음 함수 `0x4401c0`을 4단계 안에서 부르지 않음. 마우스만 menu2(`0x4589a9`).
  - Enter: `0x45fb33` → `0x461bc0`
  - ←/→: `0x403900`·`0x403b70` → `0x443d00`(SetCursorPos)
  - Esc로 열기: `0x461590` → `0x443ce0`
- **다시 시작**: 다섯 길(`0x458a19`, `0x458b45`, `0x45aa37`, `0x461ce4`, `0x461e33`)이 모두 같은 순서로 부름.
  - `0x4542d0`이 플레이어 배열을 지우고 새로 만듦(`0x463250`/`0x4632a0`). 생성자 `0x44fc50`이 `+0x204`를 0으로 함.
  - 그다음 `CHAT_open(0)`(`0x418cd0`)이 `[0x48c0e8]` = 0으로 하고 입력 글을 비움.
- **고리**:
  - 오브젝트 배열 할당 `0x411670`은 프레임 타이머 `+0x14`를 두지 않음. 진행은 부호 없는 비교(`0x4117cd`)라 처음 그릴 때 곧바로 진행.
  - 카운트다운은 페이드로 시작하고, 나가기 11프레임은 프레임 함수를 건너뜀(`0x405e08`).
  - bomb8은 오브젝트마다 부르지만 같은 정적 버퍼를 되감을 뿐임.

## Results

- **대기 화면**:
  - 2라운드부터 결과 화면 그림(손님 "준 비 중 ..") 위에 "준 비 완 료   "를 찍음.
  - Chromium 2인 대전의 2라운드 대기 화면에서 바뀐 픽셀은 셋째·넷째 글자 칸뿐임. 배경으로 돌아간 "중" 잉크는 0개.
  - 따로 그려 대조하니 겹친 글은 "준 비 완 료"만 찍은 것과 9픽셀(아래 글 외곽선) 다르고, 남은 노란 잉크는 0.
  - 원본처럼 줄마다 상태 바로 뒤에 찍고 DRAW(272,254, 251×67)는 모든 줄 뒤에 그림(`0x410552`). DRAW가 둘째 줄 상태(y 245–258)와 겹치므로 순서가 드러남. 순서를 고친 뒤에도 비무승부 라운드의 차이는 같은 165픽셀. 무승부 라운드는 브라우저로 만들지 못해 코드로만 맞춤.
- **상자 소리**:
  - 연습 끝 상자에서 Enter로 답하면 효과음이 0번, YES를 클릭하면 menu2가 한 번 남.
  - 확인 방법: Chromium에서 `AudioBufferSourceNode.start`를 가로채 버퍼 길이 37822로 식별. 테스트 프로필의 효과음 설정만 잠시 켰다가 되돌림.
  - 온라인 경기 종료 상자는 같은 방식으로 고쳤지만 브라우저로는 확인하지 않음.
- **다시 시작**: 말한 지 5초가 안 되어 다시 시작해도 페이드 뒤 말풍선 자리가 말하기 전과 같음. 열어 둔 채팅 줄도 닫힘.
- **고리**:
  - 시뮬레이션 테스트로 전환 틱과 다음 10틱은 멈추고 11틱째부터 움직임을 확인.
  - Chromium 2인 대전(snowearth02): 전환 틱(dt 0)이 첫 나가기 프레임(밝기 약 151의 0.9배 = 136)이고 dt 9–10이 검정이다. 고리는 dt 11에 처음 움직인다. 이는 원본의 페이드 호출 뒤 12번째 반복, 즉 들어오기 첫 그리기에 해당한다. 처음에는 `>`로 비교해 dt 12였던 것을 `>=`로 고쳤다.
- **검증**: `tsc` 오류 0, `vitest` 583개 통과(47파일), `vite build` 성공, `pytest` 100개 통과.
- **덧붙임(보고 뒤)**:
  - §19 매크로 칸 캐럿: 줄 첫 칸 기준 x = 원점 + 6·max(0, 캐럿 − 12·줄)(`0x403e90`의 `jle` 고정, 1줄은 `0x403e70`). 고정이 없던 복원판을 고치고 테스트를 더함. `0x403e90` 식에 맞춘 테스트로만 확인했고 Chromium의 대기실 → 리모컨 → OPTION 길로는 재지 않음.
  - §6 효과 목록: 입력 확인(`0x458750`)이 QPC 30 Hz 문 밖에서 도는 것까지 적고, 첫 프레임이 2–3번 그려지는지는 I로 남김(코드 변경 없음).
  - 다시 검증: `tsc` 오류 0, `vitest` 584개 통과(47파일), `vite build` 성공, `pytest` 100개 통과.

## Residual risks

- **손님이 준비되는 때(R)**: 원본은 손님마다 월드를 다 읽은 뒤 바뀌지만, 복원판은 서버가 모두 읽혀 대기 화면 첫 프레임부터 "준 비 완 료"다. 1라운드(`new_load`)도 같다.
- **온라인 종료 상자 소리**: 코드만 고쳤고 온라인 경기에서 소리를 재지 않았다.
- **고리 첫 프레임**: 원본 타이머 `+0x14`는 채우지 않은 힙 값이라, 우연히 직전 한 주기 안의 값이면 한 프레임 늦는다(무시).
- **페이드 길이 맞춤**: 시뮬레이션은 전환 틱을 나가기 첫 프레임으로 센다. 화면의 페이드는 rAF 프레임으로 그려져, 밝기 샘플과 틱이 ±1프레임씩 엇갈린다. 온라인에서는 스냅숏이 늦게 와 몇 프레임 더 어긋날 수 있다.
