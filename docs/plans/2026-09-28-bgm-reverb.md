# 쉐이크2 복원: 배경음 리버브(DirectMusic 기본 합성기)

## Goal

배경음을 원본이 들리던 소리에 맞춘다. 원본은 DX7 인터페이스(`IDirectMusicPerformance` v1)로 기본 포트를 쓰고, 이 포트의 DLS 합성기는 리버브(Waves TrueVerb를 옮긴 SimpleVerb)가 기본으로 켜져 있다. 복원판 렌더러(`tools/shakefmt/synth.py`)는 지금 리버브를 넣지 않는다(FIDELITY §2.1 R).

## Scope

근거:

| 항목 | 내용 | 근거 |
|---|---|---|
| 원본 호출 | `CoCreateInstance(Performance)` → `Init(NULL, NULL, NULL)` → `AddPort(NULL)` → 로더 → 세그먼트 `SetParam(StandardMIDIFile, Download)`. 리버브·효과 속성, `IKsControl`, `IDirectMusicPort` GUID가 실행 파일에 없음 | `0x43f850`–`0x43f9a5`, GUID 표 `0x4670f0`–`0x467170` |
| 문서 | DX7 인터페이스의 DLS Level 1 합성기는 리버브가 기본으로 켜짐(SimpleVerb). DX8 이후 인터페이스의 합성기는 내장 리버브 없음 | DirectX 9 SDK "Downloadable Sounds" |
| 헤더 | `DMUS_WAVES_REVERB_PARAMS` 기본값: 입력 0 dB, 믹스 −10 dB, 잔향 1000 ms, 고역 비율 0.001. 믹스는 전체 레벨이 거의 같게 계수를 잡음 | DX8.1 `dmusicc.h` 주석 |
| 실측(이 PC) | 64비트 `dmsynth.dll`: DX7 크기 `DMUS_PORTPARAMS`로 효과 플래그 없이 기본 포트를 만들면 발음 32, 22050 Hz, 2채널, 효과 `0x1`(리버브), 리버브 값이 헤더 기본값과 같음 | `IDirectMusic::CreatePort` 반환값, `IKsControl` GET |

범위:
- 실제 `dmsynth.dll`로 리버브의 2×2(좌·우 입력 → 좌·우 출력) 임펄스 응답과 원음 이득을 잰다. 소리는 내지 않는다(음량 최소 버퍼, 재생 중 확정 구간만 복사).
- `bgm.py`가 잰 응답이 있으면 모든 곡(게임 14곡, 로비·대기실)에 걸어 다시 렌더한다. 없으면 지금처럼 리버브 없이 렌더하고 알린다.
- 잰 응답과 렌더 결과는 로컬 전용이다(`assets/extracted/`, 재배포하지 않음). `gm.dls`와 같은 취급.

범위 밖:
- 합성기 전체(엔벨로프·발음 관리 등)를 실제 합성기와 곡 단위로 대조하는 일. 64비트에는 Performance 계층(`dmime.dll`)이 없어, 포트에 이벤트를 직접 넣으면 시계가 20초에 약 25 ms 흐른다. 따로 할 일로 남긴다.
- 코러스: 포트 능력이 `0x1`(리버브만)이라 원본에도 없다.

## Approach

- **측정 하네스(`tools/dmsynth/`, Windows Python + ctypes, 표준 라이브러리만):**
  - `IDirectMusic`(v1) 기본 포트에 자체 DirectSound 버퍼(음량 −10000)를 `SetDirectSound`로 연결한다.
  - 이벤트를 `PackStructured`/`PlayBuffer`로 보내고, 재생 중 [재생 커서, 쓰기 커서) 구간을 복사한다. 싱크는 재생이 지난 구간을 곧 지우므로 끝나고 읽으면 비어 있다.
- **임펄스 악기:** `gm.dls`에서 영역 하나에 루프 없는 악기를 떼어 파형만 한 샘플 임펄스로 바꾼다. 직접 만든 DLS는 합성기가 `DMUS_E_INVALIDOFFSET`으로 거절해서다. 파일은 임시로만 두고 지운다.
- **풀이(`tools/shakefmt/dmreverb.py`):**
  - 캡처는 음 시작부터 비트 단위로 결정적이라 평균으로 잡음이 줄지 않는다. 고정소수점 바닥(직류성 몇 LSB)은 입력 크기와 무관하다.
  - 그래서 팬마다 리버브를 켠 큰 캡처(4·5음)에서 작은 캡처(1음)를 빼 바닥을 상쇄하고, 왼쪽 끝·오른쪽 끝 차이로 주파수마다 2×2를 푼다.
  - 큰 캡처의 원음 샘플은 출력에서 잘리지만, 리버브는 잘리기 전 값을 받는다(실측). 잘린 원음 샘플 자리는 풀이에서 뺀다.
  - 원음 이득은 작은 캡처 ÷ 끈 캡처로 잰다.
  - 응답은 10 ms 구간 전력이 측정 잡음의 2배 아래로 내려가는 곳에서 자른다.
  - 가운데 팬 차이를 예측해 검증한다.
- **적용(`tools/shakefmt/reverb.py`):**
  - 출력 = 원음 이득·x + Σ h⊛x이다(float 믹스에 걸고 마지막에 클리핑).
  - 실측으로 확인한 두 사실을 따른다. 리버브는 포화 전 합산을 받고, 좌우를 따로 처리한다.
  - 꼬리까지 렌더해 두면, 클라이언트가 반복을 `loopEnd`에 겹쳐 재생해 원본의 연속 잔향과 같아진다(선형).
- **테스트 먼저:** 적용식(지연 임펄스 응답, 2×2 경로, 길이), 저장·읽기, 2×2 풀이(합성 데이터).

## Results

- 원본 경로 확인(32비트 프로브, 스크래치): `Performance v1` → `Init(NULL, NULL, NULL)` → `AddPort(NULL)` → `PChannelInfo(0)` 포트는 "Microsoft Synthesizer", 22050 Hz 16비트 스테레오, 채널 그룹 1, 효과 `0x1`, 리버브 0 / −10 / 1000 / 0.001.
- 측정(`python -m shakefmt.dmreverb`, 64비트):
  - 원음 이득 0.94862(헤더 0.94868), 첫 반사 45.0 ms(L)·32.4 ms(R), 응답 0.659초.
  - 큰 캡처 ÷ 작은 캡처의 젖은 소리 비례 0.9997–0.9999(음당).
  - 가운데 팬 예측 오차 −34.8 dB(첫 0.3초 −44.7 dB).
  - 첫 측정은 3음 포화와 전역 직류 제거로 탭 0이 −0.03, 오차가 −19 dB였고, 2음 차분은 −22.6 dB(꼬리 잡음)였다.
- 선형 범위: 1·2·4음 비례, 8·14음은 리버브 입력 포화(젖은 소리 최고값 9756 고정, 입력으로 약 2배 풀스케일).
- 32비트 합성기로 같은 임펄스를 뜨면 0.1초 뒤로 64비트와 비트 단위로 같고, 첫 0.1초 차이(0.04 LSB rms)는 끝 팬 반대편 입력 668 대 662로 설명된다.
- 리버브 센드: CC91 0·127 캡처가 보내지 않은 캡처와 비트 단위로 같다(믹스 전체 효과). 곡들은 CC91·CC93을 쓰지 않는다(컨트롤러 0·7·10·32뿐).
- 드럼: `gm.dls` 표준 킷 스네어(채널 10)를 잰 응답으로 예측하면 젖은 소리 대비 오차 −32.9 dB.
- 렌더: 16곡 모두 길이가 0.658초 늘고, 최고 레벨 변화는 −0.8~+0.5 dB. 클리핑은 `mission to mizar`가 4 → 10샘플, 나머지는 0.
- 브라우저(Chromium, 개발 서버):
  - 16곡 모두 200, 22050 Hz로 디코드되고 길이는 `loop_end` + 꼬리.
  - 연습 화면에서 `tbwait11.ogg`(65.602초)가 0.201초에 시작하고, 다음 반복이 62.132초(= +61.931)에 예약되어 3.67초 겹친다.
  - 콘솔 오류·경고 없음.
- `npm run sync-assets`는 `public/assets`를 지우고 다시 만든다. 이때 떠 있던 Vite 개발 서버는 모든 자산 요청을 `index.html`로 돌려서 서버를 다시 시작해야 했다(README에 적음).
- 검증: 도구 pytest 82, vitest 36파일 489, tsc, 빌드.

## Residual risks

- 2002년 당시 런타임(DirectX 8.1, Windows 98/2000/XP)의 `dmsynth.dll`이 이 PC의 것과 같은 리버브 코드라는 것은 추론이다.
- 리버브 입력 포화(약 2배 풀스케일)는 모델에 넣지 않았다. 지금 곡들은 +0.6 dBFS가 최고라 영향이 없다.
  - 뒤에 고침(`2026-09-28-bgm-real-synth.md`): +0.6 dBFS는 절반 크기로 렌더한 값이었다. 제 크기에서는 mission to mizar가 +6.3 dBFS이고, 2배를 넘는 샘플은 3개뿐이라 여전히 넣지 않는다.
- 합성기 나머지와 곡 단위로 대조하는 일은 범위 밖으로 남는다.

## Threat note

- 이 PC의 Windows Python(`py.exe -3.9`)과 이미 설치된 DirectMusic DLL을 실행한다. 새로 받거나 설치하는 것은 없다(pip 없음).
- 32비트 대조용 C# 프로브는 Windows에 있는 .NET Framework `csc.exe`로 스크래치에서 컴파일해 실행했다. 프로젝트에는 넣지 않았다.
- 쓰는 파일은 스크래치와 `assets/extracted/`(로컬 전용)뿐이다. 임시 DLS는 측정 뒤 지운다.
- 네트워크 접근은 없다.
- 소리는 음량 최소 버퍼로 내보내 스피커로 나가지 않는다.
- 하네스는 COM 포인터를 ctypes로 부른다. 실패하면 그 프로세스만 끝나고 시스템 설정은 바꾸지 않는다(레지스트리·장치 설정 쓰기 없음).
