# 계정과 계정 데이터, 색조, 서버 기능

## Goal

"부족한 부분"의 1·2번을 채운다.

1. 원본 데이터 없이도 만들 수 있던 것: 색조(0x414760, 장면 5와 내 정보의 색조 창), 로비 사용자 정보 창, NEW ID(가입) 창.
2. 원본 서버 데이터가 없어 비어 있던 것: 계정 데이터(길드, 순위, 레벨, 전적, 셀포인트, 사탕, 성별), 상점·아이템(강퇴·마스크 아이콘, 닉네임 창), 랭킹(장면 12 창과 장면 5 쪽), 서버 기능(인증, 여러 서버와 색, 공지 줄, 정원·중복 로그인·레벨 거절, 버전 확인).

원본 서버 코드는 없으므로 서버의 규칙은 복원판의 것(R)이고, 클라이언트 쪽 화면·좌표·문구·순서는 역공학 기록(`$S/re_work/findings_*.md`)을 따른다.

## Scope

- 서버: 계정 저장소(JSON 파일, scrypt), 가입·로그인·세션, 계정 필드의 전송, 경기 결과 반영, 랭킹, 아이템·상점, 채널(여러 로비), 공지, 정원, 버전.
- 클라이언트: 로그인 흐름(인증 접속), NEW ID 창, 사용자 정보 창, 계정 필드를 그리는 모든 곳(로비 줄, 내 정보, 방 슬롯, 방 정보, 친구 목록, 게임 패널, 결과 화면), 색조(경로 a·b), 랭킹 창, 닉네임 창, 상점, 공지 줄, 서버 줄 색.
- 도구: `.spr`의 8비트 원본을 `<name>.rgb.png`로도 내보내 색조 경로 (a)를 비트 단위로 맞춘다(`tools/shakefmt`, `sync-assets`).
- 문서: README(서버 환경 변수, 계정, 개인정보), FIDELITY 해당 줄(R/I/V), 이 계획의 Results.
- 범위 밖: 실제 결제·돈(원본도 "현재 지원안함"), 업데이트 프로그램(shupdate.exe), 이메일 발송, 비밀번호 찾기(원본에 없음), 관리자 화면.

## Approach

### 결정 (조언자 검토 반영)

- **인증 접속 위치와 오프라인.** 원본처럼 로딩 1→3에서 서버에 접속한다. 실패하면 로그인 화면 위에 "인증서버 접속 실패". 이 경우 OK는 지금의 무인증 경로(장면 5, 연습, 2인 대전)로 가고, 서버 줄은 실패로 보인다(R: 서버 없이도 연습·2인 대전이 되어야 함). 메시지 상자의 OK/Esc는 다시 접속한다(0x461635). "로그인 실패"(계정·암호 틀림)는 오프라인으로 가지 않는다.
- **세션.** 로그인 응답 `{account, token, channels}`. 게임 서버 접속은 `version {version, channel}` → `hello {token}`이고(정원이 차면 버전 답 전에 끊음), 이름·캐릭터는 계정에서 온다. 토큰은 `randomBytes(32)`, 서버 메모리에만(브라우저 저장소에 두지 않음), 채널을 바꿔도 다시 쓴다. 같은 계정이 이미 채널에 있으면 코드 2 "이미 로그인 되어 있습니다".
- **개인정보.** 주민등록번호 수집은 개인정보 보호법 제24조의2로 금지되므로 주민번호 두 칸은 쓰지 않는다(초점 없음, Tab 건너뜀, 검사 9와 rcode 2/3/6 없음). 성별은 원본이 주민번호에서 얻으므로 모두 0(아이콘 없음, 원본 코드가 그리는 그대로). 이름·이메일·지역은 사용자 정보 창으로 모두에게 보이므로 역시 쓰지 않는다(검사 7·8·10·12 없음, 기입 단추는 그림만). 약관 5줄 자리는 복원판이 저장하는 것(ID, 닉네임, 비밀번호 해시, 기록)을 알리는 짧은 글로 바꾼다(R, 되돌릴 수 있는 결정으로 보고).
- **색조.** 경로 (b)(Wg_char, 565에서)는 지금 PNG로 비트 단위가 된다. 경로 (a)(`.spr`, 8비트에서)는 `<name>.rgb.png`를 읽어 행 첫 픽셀과 같은 픽셀은 건너뛰고, 돌리고, 565로 자르고 넓힌 뒤, 왼쪽 위 픽셀로 키를 잡는다(doona_w 줄무늬까지 재현). 색조 0은 지금 PNG 그대로. 경로 (b)의 색조 0은 항등이 아니므로 창을 열 때와 46×40 머리에서도 돌린다.
- **경기 결과.** 원본은 클라이언트가 셀 몫을 계산해 보고(C→S 0x4e)하지만, 복원판 서버는 경기를 직접 돌리므로 서버가 같은 식으로 계산하고 클라이언트 보고는 받지 않는다.
- **신원.** `profile.name`은 로그인 ID(로비 줄은 항상 ID). 닉네임과 useId는 원본이 +0x68로 고르는 곳(방 슬롯, 게임 패널)에서만. 친구 목록은 ID로 이어서 지금 friends.json이 그대로 쓰인다.
- **레벨.** 백분위 표를 로그인과 랭킹 요청 때 계산한다(R: 원본은 하루 한 번).
- **버전 불일치.** 상자에 res#37 문구, 상자를 닫으면 `location.reload()`(되풀이 없음).

### 보안 (위협 메모는 Results에)

- scrypt(`node:crypto`), 계정마다 소금, `timingSafeEqual`. 새 런타임 의존성 없음.
- 로그인·가입·ID/닉 확인에 주소별 간격(`PasswordGuard` 모양).
- 계정 파일은 0600, 임시 파일+rename, 깨진 파일은 옆으로 옮김(`friendFile.ts`와 같음).
- `parseClientMessage`가 새 필드를 모두 cp949 바이트로 묶는다(ID 4..10 영숫자·숫자로 시작 않음, 닉 ≤10, 암호 4..10).
- 색조는 서버가 ±180으로 자름. 사용자 정보 창이 그리는 필드만 전송.
- `startupWarning`은 계정 암호도 평문으로 간다고 말한다. 암호 10바이트 한도는 원본 그대로이며 약함을 메모에 적는다.

### 위협 메모 (인증·비밀·개인정보·네트워크)

- **저장.** 비밀번호는 scrypt(N=16384, r=8, p=1, 16바이트 소금, 32바이트 키)만 저장하고 `timingSafeEqual`로 비교한다. 없는 ID도 미끼 해시로 같은 시간 검사를 해 응답 시간으로 ID 존재를 드러내지 않는다. 계정 파일은 0600이고 공개·배포하지 않는다.
- **약한 비밀번호.** 원본 편집기대로 4~10바이트라 짧다. 온라인 추측은 주소별 직렬 처리와 실패마다 0.5초부터 30초까지 두 배로 늘어나는 지연(10분 뒤 잊음)으로 늦추고, 파일이 새면 오프라인 추측은 scrypt 비용만 막는다.
- **전송.** TLS(`TLS_CERT`·`TLS_KEY`) 없이 루프백 밖에서 들으면 ID·비밀번호·토큰이 평문으로 가므로 시작할 때 경고한다. LAN 밖 공개에는 TLS나 TLS 끝단 프록시가 필요하다.
- **세션.** 토큰은 `randomBytes(32)`의 base64url, 서버 메모리에만 두고 브라우저 저장소에 두지 않는다. 계정마다 하나라 새 로그인이 이전 토큰을 무효로 하며(마지막 로그인이 이김), 12시간 쓰지 않으면 만료된다. 서버를 다시 시작하면 모두 무효.
- **열거.** `check-id`·`check-nick`은 원본 가입 창의 기능이라 ID·닉 존재를 알려 준다. 주소별 250ms에 한 번으로 묶어 대량 열거를 늦추되 막지는 못한다. 가입은 주소별 10초에 한 번(성공한 것만 셈).
- **자원.** 연결마다 기다리는 요청은 하나, 인증 요청은 주소별로 차례로 처리한다. 정원(`MAX_USERS`)은 버전과 hello 사이의 연결까지 센다.
- **개인정보.** 실명·주민등록번호·이메일·지역은 받지 않는다(주민등록번호는 개인정보 보호법 제24조의2, 나머지는 사용자 정보 창에 모두에게 보이는 필드라서). 되돌릴 수 있는 결정이며 NEW ID 창에서는 칸을 그림만 남긴다.
- **시험.** `gate.test.ts`: 틀린 암호 지연, 주소별 한 번에 하나, 가입·확인 간격, 낡은·없는 토큰 거절, 중복·레벨 거절, 정원, 버전 불일치 뒤 hello 거부, 로그인 전 요청 거부, 닉네임 규칙. `server.test.ts`: 실제 소켓으로 로그인·중복·정원·TLS 로그인.
