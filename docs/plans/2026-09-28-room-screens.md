## Approach

- 서버: 방 번호(서버 안에서 가장 작은 빈 번호)와 제목, 맵 RANDOM, 음악 선택(RANDOM + 14곡, 원본 정렬 순서), 빈 슬롯 열기·닫기(방장), 방 채팅(길이·간격 제한, 입장·퇴장 문구). 메시지는 모두 `parseClientMessage`에서 검사 → 위협 메모
- 클라이언트: `roomLayout.ts`(좌표·판정, 순수 함수, 테스트), `roomScreen.ts`(캔버스 그리기·마우스·키보드). 채팅 편집기는 연습의 `ChatLine`을 한도만 바꿔 다시 씀
- 접근성: 캔버스는 원본처럼 마우스 화면이고, 기존 DOM 조작(모드·팀·맵·준비·시작·나가기)을 캔버스 아래에 그대로 둬 키보드·화면 낭독기 경로로 씀. 채팅 줄은 live 영역으로 읽힘
- 방 코드: 원본에 없는 복원판 참가 방식이라 캔버스 밖 머리줄에 둠
- 테스트 먼저. 실제 UI는 두 페이지로 확인

## Steps

1. 서버·프로토콜: 방 번호·제목, 음악·맵 RANDOM, 슬롯 열기·닫기, 채팅
2. `roomLayout.ts`: 좌표표, 판정, 채팅 줄바꿈·스크롤, 드롭다운
3. `roomScreen.ts`: 그리기 순서, 올림·누름, 드롭다운, 도움말, 공지, EXIT 상자, 채팅 입력
4. `online.ts`: 방 화면 교체, DOM 조작 유지, 음악
5. FIDELITY §13, README, 실제 UI 확인
6. 방 목록·방 만들기 창
   1. 서버·프로토콜 3: 로비 상태(방 요약·로비 사용자·채널 이름) 방송, 로비 채팅, 방에서 나오면 로비로
   2. `lobbyLayout.ts`: 좌표·판정·쪽 넘김·필터
   3. `lobbyScreen.ts`: 캔버스 로비, 방 만들기 창, 메시지 상자, 리모컨 창
   4. `online.ts`: 입장 화면 → 로비 → 대기실 → 로비. DOM 조작(방 목록 버튼, 만들기, 코드로 참가, 로비 채팅, 나가기) 유지
   5. FIDELITY §14, README, 실제 UI 확인

## Threat note (프로토콜 변경)

- 새 메시지: `create-room.title`(문자열 64자 이하 → cp949로 칠 수 있는 글자만, 앞뒤 공백 제거, 19바이트), `set-music`(정수 0~99, 방에서 곡 수 이하), `set-slot`(정수 0~5, 불리언), `chat`(문자열 200자 이하 → cp949 글자만, 끝 공백 제거, 45바이트 미만, 빈 줄 거부). 모두 `parseClientMessage`에서 검사하고 그 밖은 버림.
- 채팅은 서버가 보낸 사람의 이름을 붙여 방 안에만 보냄. 사람마다 같은 줄 반복과 2초 안의 줄을 버려 방 안 도배를 막음. 게임 중에는 받지 않음. 클라이언트는 채팅을 `textContent`로만 넣어 HTML로 해석하지 않음.
- 방장만 음악·맵·슬롯을 바꾸고, 게임 중에는 못 바꿈. 빈 슬롯만 닫을 수 있음. 모두 서버가 검사함.
- 제어 문자와 cp949 밖 글자(이모지, 양방향 제어 문자 포함)는 제목·채팅에서 빠짐. 메시지 크기 제한(4096바이트)과 초당 메시지 제한은 그대로. 새 의존성 없음.
- 6단계(프로토콜 3): 로비에 있는 모든 접속자가 방 목록(방 코드·번호·제목·맵·모드·인원·게임 중)과 로비 사용자 이름을 받음. 원본도 방 목록을 공개하므로 의도한 동작이지만, 이전(방 코드를 아는 사람만 참가)과 달리 방 코드가 공개됨. 비공개 방이 필요하면 원본의 비밀방·암호가 따로 있어야 함(범위 밖).
- 로비 채팅은 방 채팅과 같은 검사(45바이트 미만, 반복·2초 제한)를 서버에서 하고 로비에 있는 사람에게만 보냄. 방 정보 요청 `room-info`는 `isRoomCode`로 검사하고 있는 방에만 답하며, 답은 방 목록에 이미 보이는 정보와 자리별 이름뿐이라 새로 드러나는 것이 적음. 요청은 기존 초당 메시지 제한을 받음. 채널 이름(`CHANNEL`)은 서버 운영자 설정이며 cp949 16바이트로 자름.
