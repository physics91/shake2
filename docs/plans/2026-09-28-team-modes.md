# 쉐이크2 복원: 팀전·화력·소환 모드

## Goal

원본 대기실의 게임 방식 8가지(개인전, 자유/매너 팀 매치, 화력 개인전·팀매치, 소환 팀매치)를 복원판 온라인 대전에 넣는다.
근거는 `re_work/findings_team_rules.md`(규칙), `findings_team_ui.md`(방·HUD·결과 화면), `findings_items_roll.md` §1.6, `findings_obj_gen.md` §1.3(화력 확률표)이다.

## Scope

| 항목 | 원본 | 근거 |
|---|---|---|
| 모드 판정 | 팀 = mode ∉ {0,3}, 화력 = 3–5, 소환 = 6–7. 자유/매너는 클라이언트에서 구분 없음 | `0x440680` 55곳 전수 |
| 팀 | 방 슬롯 +0x74, 1..6. 만든 사람 1팀. 준비 중에는 바꿀 수 없음 | `0x444dbe`, `0x448970` |
| 아군 공격 | 늘 켜짐, 모든 상호작용에 팀 필터 없음 | 전수(부재) |
| 라운드 판정 | 살아 있는 사람이 모두 한 팀이면 그 팀 승. 아무도 없으면 마지막으로 죽은 사람의 팀. 시간 초과 DRAW | `0x441130` |
| 메달·끝 | 이긴 팀 모든 슬롯 +1(죽은 사람 포함). 3승 또는 남은 사람이 모두 이긴 팀이면 매치 끝. 개인전도 한 명만 남으면 끝 | `0x4410c0`, `0x441130` |
| 화력 | 벽돌 확률표와 제너레이터 확률표만 다름 | `0x44e47f`–`0x44e5fb`, `0x417f00` |
| 소환 | 죽는 애니 끝에 그 칸에 캡슐(0x21). 누구나 줍고, 주운 사람 팀의 죽은 사람 하나를 되살림 | `0x453270`, `0x453d00` |
| 화면 | 같은 팀 머리 위 diff2, 투명 아군 반투명, 패널 이름 팀 색, 결과 화면 teambar | `0x40a9f1`, `0x40ab74`, `0x404206`, `0x442580` |
| 방 | 방장이 모드 선택(8가지), 팀 버튼 6개, 팀 모드 시작 시 팀이 둘 이상이어야 함 | `0x428340`, `0x425d6e`, `0x44a2c3` |

범위 밖: 방·로비 화면의 원본 그림(복원판 방은 DOM), 방 목록의 모드 아이콘, 네트워크 채팅과 채팅 중 이름표(후속), 매치 끝 점수(표시되지 않음).

## Approach

- 시뮬레이션: `Rules.mode`(0..7)와 `modes.ts` 판정 함수. `PlayerSetup.team`/`PlayerState.team`(개인전 0)
- 라운드·매치 판정을 원본 `0x441130` 순서대로. 이벤트와 상태에 이긴 팀(`winnerTeam`)을 더함
- 화력: `rollBrickItem`, `generatorItem`에 화력 분기. 난수 호출 횟수도 원본과 같게
- 소환: `ItemKind.Capsule`(33). 죽는 애니 끝 `scatterItems` 앞에서 떨굼(0x410920 조건), 줍기에서 되살리기. 효과 `revival`(한 번, 따라감)
- 되살리기 난수: 원본은 `srand(time(0))` 뒤 `rand() % n`. 시뮬레이션 난수열을 그대로 씀(R)
- 화면: 다른 플레이어 반복(0x40a964, 자기 자신 제외)에서 diff2와 투명 아군. 결과 화면 teambar
- 서버: `set-mode`(방장, 게임 중 아님), `set-team`(1..6, 준비 중 아님, 팀 모드에서만). 들어온 사람 기본 팀은 서버가 정함(원본 값 모름): 1팀과 2팀 중 적은 쪽(R)
- 테스트 먼저, 30 Hz 틱

## Steps

1. 시뮬레이션: 모드·팀 필드, 팀 라운드·매치 판정, 개인전 한 명 남음 규칙
2. 화력 확률표(벽돌·제너레이터)
3. 소환 캡슐 떨굼·줍기·되살리기, revival 효과
4. 화면: diff2, 투명 아군, 패널 이름 색, 결과·대기 화면 teambar, 안내 문구
5. 서버·프로토콜·방 UI(모드 선택, 팀 버튼), 위협 메모
6. FIDELITY 팀 절, 136행 정정, README, 실제 UI 확인(두 브라우저 페이지)

## Threat note (프로토콜 변경)

- 새 메시지 `set-mode`(정수 0~7), `set-team`(정수 1~6)은 `parseClientMessage`에서 형식·범위를 검사하고 그 밖은 버림(테스트 7건).
- 모드는 방장만, 게임 중에는 못 바꿈. 팀은 자기 것만, 팀 모드에서만, 준비 중이 아닐 때만. 모두 서버가 검사하고 클라이언트 표시는 참고용.
- 메시지 크기 제한(4096바이트)과 방 브로드캐스트 양은 `set-map`과 같은 수준. 새 의존성 없음.
